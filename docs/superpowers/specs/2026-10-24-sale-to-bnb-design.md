# Fast explicit sale to BNB

User requests quicker sales, automatic conversion of received quote assets to BNB, proven realized PnL and a complete portfolio plus current sale PnL after completion. Prior user opted out of repeated workflow questions; execute on existing stack, never real-trade during implementation. Selling still requires an explicit human sale; new policy automaticSaleConversion opts in to converting only current sale proceeds, never pre-existing quote inventory. Default slippage1%, max5%, no widening/retry/claim.

Chosen approach: durable SALE_BNB_V1 parent links separately persisted SELL_V1 and EXIT_V1 legs. Same local process continues after receipt confirmation; restart requires read-only recovery first and explicit same-request --resume for unsubmitted next leg. Each financial boundary persists before submission. Parent-child exclusion is narrowly validated, other unresolved intents block. Distinct roundtrip coordination lock plus existing wallet lock protects each leg; parent blocks unrelated financial requests between legs. Alternative atomic router unsupported by existing official ABI; chat-sequenced commands add latency and recovery risk.

Snapshot/reuse only initial assessments. Batch independent pinned token code/balance/decimals/symbol reads; do not quote conversion until actual sale amount known. One exit of exact actual received raw amount. Partial refund retains assets and proportional basis, no automatic sweep/retry. Native sale uses no exit. Return confirmed effect immediately; separate readonly portfolio job shows all holdings and current sale report.

Actual BNB proof: transaction-specific readonly call trace, sum successful wallet native transfers, excluding reverted subtrees and delegatecall value duplication. Canonical hash/receipt checked around proof. No quoted/reported output used as actual. Unsupported/unreadable trace => proceeds/PnL unknown, readonly archive fallback in statistics, never repeat a trade. Cost from proven position basis matching approved prior shares, exact proportional allocation; net PnL subtracts allocated purchase cost/gas plus sale and conversion gas once. Per-sale settlement records remain distinct from cash/accounting events; historical realized display only complete covered sales.

No conversion of prior flapai sale or any other existing balance this task. No automatic sale timing. No real transactions, credentials or private state publication.
